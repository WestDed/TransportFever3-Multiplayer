## Реальные дефекты, исправленные в проекте

`C.deser` вызывал `load("return "..s)` и исполнял полученную функцию. Пустое окружение не запрещает объявление функции, цикл и вычисления. Теперь вход никогда не передаётся компилятору Lua: рекурсивный разбор создаёт только значения данных. Остались только доверенные `load` в тестовом загрузчике и в oracle теста на **собственном C.ser output**, не на враждебном вводе.

Обработчик bridge раньше заменял неразобранное сообщение на `{}`; для `session` это могло сбросить started/speed. Теперь неверное значение или корневой scalar игнорируются. Контроль resync и результаты UI также требуют таблицы. Это проверено отправкой повреждённых/исполняемых сообщений через реальные файловые входы Lua-мода; скорость остаётся прежней и загрузка/сохранение не запрашиваются.

Независимый C# `LuaLit.Table` при неверном символе вызывал `Value`, которая не продвигала индекс. Такое поведение могло оставить программу запуска в бесконечном цикле. Разбор теперь либо потребляет токен, либо возвращает отказ; неполные таблицы, хвосты, duplicate keys и нечисловые выражения не принимаются. Сохранён публичный `Parse(string)` и ожидаемая форма Dictionary. Большие конечные numeric keys не приводятся к long с переполнением.

## Формат и ограничения

Сеть остаётся прежней: UTF-8 строка `kind TAB from TAB payload LF`. Распорядитель действий, transport, native hooks и финансовые правила не переписаны.

Допустимы `nil`, `true`, `false`, конечные десятичные числа (включая знак минус и exponent), короткие quoted strings и таблицы `{[key]=value,...}`. Ключ — string/number/boolean. Поддерживаются sparse numeric arguments с полем `n`, вложенные arrays/records и decimal escapes 0..255; проверены все 256 байтов и Unicode. Повторный key отвергается, даже если первое значение nil. Поле с nil отсутствует в результате, как в Lua.

Имена переменных, вызовы, операторы, функции, комментарии, bytecode, hex numbers, long-bracket strings, table keys и shorthand constructors `{x=1}`/`{1,2}` не являются wire grammar. Ни `C.ser`, ни формирование сообщений программы запуска такую shorthand форму не используют. Это сознательное сужение прежнего произвольного Lua, а не поддержка всего синтаксиса языка.

| Предел | Значение |
|---|---|
| Вход целиком | 4 MiB; Lua считает байты, C# проверяет UTF-8 byte count и предварительную длину строки |
| Вложенные таблицы | 40, соответствует глубине `C.ser` |
| Поля во всех таблицах суммарно | 100 000, включая поля с nil |
| Строка после декодирования | Lua: 1 MiB байтов; C#: 1 048 576 UTF-16 units |
| Числовой токен | 128 символов, только конечный результат |

Лимиты действуют и на местные `C.ser/C.deser` копии. Проверена обычная часть передачи сохранения: 256 KiB binary → около 350 KiB base64. Unicode и byte strings в двух runtime имеют разные units для decoded-string ceiling; общая входная граница остаётся UTF-8. Очень большие реальные строительные предложения ещё не измерены: если они превысят предел, требуется осознанная корректировка с тестами, а не отключение защиты.

Это не полная защита сетевого режима. `ReadLine`/file read всё ещё выделяют память **до** декодирования; аутентификация Steam identity, peer→company, schema полей каждой команды, rate limiting, очередь и лимиты полного snapshot — следующие задачи. Корректная таблица с неверными по смыслу полями ещё может быть отвергнута только обработчиком/движком. Подпись реестра без sid (AUD-04) не менялась.

## Проверки и CI

| Настоящий `LuaLit` из Core.cs, Windows | 46 checks PASS, компиляция отдельного класса через PowerShell Add-Type |
| Исходный translation report | Три известных ключа отсутствуют в 11 локалях; новое расхождение запрещено baseline gate |

Набор из 44 = 16 исходных component checks + 12 decoder regressions + 9 harness checks (один выполняет все 17 прежних assertions) + 5 translation baseline checks + 2 CI policy checks. Два запуска на разных ОС — не 88 различных тестов.

Parser regressions покрывают выражения с вызовами/циклом без компиляции, неправильные ключи/escape/trailing data, NaN/inf, лимиты на границе и за ней, all-byte roundtrip, sparse command shape, 100 generated trusted comparisons и 300 deterministic malformed inputs. Это небольшая регрессионная выборка, не исчерпывающий fuzzing.

В workflow нет `continue-on-error` для обязательных проверок. Ошибка/исключение/неожиданный успех expectedFailure дают nonzero. Отдельный policy check разрешает только одну именованную ожидаемую ошибку AUD-04; нельзя добавить новый expectedFailure незаметно. `test_lang_baseline.py --report` запускает исходную проверку и разрешает только три указанных ключа; исключения, новый missing key и broken placeholder дают nonzero. Эти исключения не были «исправлены» сменой критерия готовности.
